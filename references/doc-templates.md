# Шаблоны документов этапа 3

Протокол требует 8 документов. Это скелеты: заполняются по мере прохождения
этапов 2-6, а не в конце. Каждый шаблон начинается с пометок `[ЗАПОЛНИТЬ]`,
которые `tools/doctor.py` считает незакрытыми.

Полные заготовки лежат в `templates/` - копируются в проект командой:

    python tools/install.py --target <проект>

---

## Кому какой документ принадлежит

| Документ | Владеет решением | Не пишется туда |
|---|---|---|
| `README.md` | обзор, стек таблицей, подъём локально | обоснования, риски |
| `ARCHITECTURE.md` | диаграмма, поток запроса, слои, путь масштабирования | детальные контракты |
| `API_CONTRACT.md` | соглашения: именование, версии, ошибки, пагинация, auth | бизнес-правила |
| `SECURITY.md` | модель угроз, меры, локализация ПД, план при инциденте | стек целиком |
| `ENVIRONMENTS.md` | локальное / staging / production, имена переменных, деплой | секреты |
| `CONTRIBUTING.md` | стандарты кода, git-флоу, ревью, коммиты | архитектура |
| `DECISIONS.md` | ADR: решение, контекст, альтернативы, статус | всё остальное |
| `CHECKLIST.md` | capability ledger: скоуп / deferred / подготовлено | детали реализации |

Правило одного дома: **решение принимается в одном документе и ссылается из
остальных.** Два документа, где одно и то же описано по-разному, разъезжаются
за месяц.

## Правила ведения

- `CHECKLIST.md` обновляется при каждом изменении объёма продукта. Это
  источник правды о том, что решено, а не память о разговоре.
- Решение, принятое вне ADR, считается непринятым.
- `[ЗАПОЛНИТЬ]` в документе означает, что решение ещё не принято.
  `tools/doctor.py` считает такие места пробелом.
